  **这两个"用道具"的任务是两种怪，道具名也不一样**：招魂帖是**招魂幡**的、逐妖蛊虫是**逐妖蛊虫**的。曾经把招魂帖的文案当成逐妖蛊虫的例子写进注释和测试（用户指出来过）——代码里四条正则只看"地图名+坐标"、不看怪名道具名，所以逻辑没错，但注释/测试/文档写错会把后来的人带沟里。`sec_bell` 里现在有一条 `六种怪的真实文案逐个认` 盯着这张表。**六条现在全是逐字原文**（2026-10-16 晚上补齐：招魂幡/逐妖蛊虫/梦魇魔 换成用户当晚给的 1:1 截图原文 —— 老版本的首句和尾巴是猜的；迷幻妖/怯弱妖=截图、巧智魔=真机 bell.log）。

  **每一拍读到的字还要过一层"话术门槛"**（`BELL_WORDS` / `has_bell_words`，用户定的 2026-10-16 晚）：面板那一拍读到的**整段文字**里必须含 `使用 / 踪迹在 / 招魂 / 蛊虫 / 妖魔 / 梦魇魔 / 迷幻妖 / 巧智魔 / 怯弱妖` 里任一个，才认那段里的"图名+坐标"；一个都没有就当**读花**（不报、也不进"待确认"，也不进 `dlg_text`；心跳里 `话术门槛挡下 N 次` 能看到它挡了几次）。挡的是**唯一一条"两遍一致"防不住的误报路径**：面板收紧失败（`box = 整块`）时会把下方的聊天/世界频道一起读进来 —— 聊天里一句「去长寿村(50,60)集合,别乱跑」正好长成"图名+坐标"，而它是**静态行**，两遍必然读成一样。门槛用"或"、都挑短的：OCR 丢一两个字还剩别的词能命中（整句模板一丢字整条就废）。**任务栏那一支不吃这道门槛**：它已经有 wide 规则 + 见过两次；更要紧的是悬停那行（`在建邺城(15,122)处`）单独读出来时**一个核心词都没有**，吃了会把 hover 档废掉。回归用例：`sec_bell` 的「话术门槛:面板里读到聊天那种「图名+坐标」被挡下」「话术门槛:六种怪的对话框原文都过得了（别把自己的任务挡了）」。

  对应到 `tools/bell.py`（**对话框优先、任务栏补充**；**已经不做"两处对不上就立刻再扫"**，2026-10-16 按用户要求整套删了）：
  - `scan_bell_parts(blocks, scoped=True, wide=False)` 把一轮文字块拆成 `(dialog, tracker, where)`：dialog =「踪迹在…」或「去X(x,y)使用…」（最权威），tracker =「妖魔在…/在…处」（任务栏或悬停），where 恒为 `None`（「去X找Y」只有图名的**一律不管**）。`_RE_BELL_TRACK` 带 `(?<!踪迹)`，不然对话框那半句的"在"会被当成任务栏说的。
  - **`wide=True` = 这一拍读的是大字面（整窗）**，只认带虚词锚点的写法（详情见下面「整窗那一拍只认带锚点的写法」那条）：`_RE_BELL_KNOWN`（光秃秃的"图名(x,y)"）不认，`_RE_BELL_ANY` 换成 `_RE_BELL_ANY_ANCHORED`（必须带"去/到"）。`_scan` 里传的是 `wide=not rect_known`；读红框那一小块（wide=False）行为一个字没变，容错照旧。
  - `BellTool.tick`：**一个杀怪周期 = 一次"对话框给出图+坐标"**（`self._cycle`）。周期内只有任务栏给出**新的图+坐标**才更新（逐妖蛊虫用道具后就是这种）；任务栏只写地图没坐标的**一律不管**（用户明确要求，界面也不显示半成品）。同一条提示不重复记（`_last`）；坐标落在地图范围外的当读花、**不报**（`in_bounds`）。
  - **扫哪**：**全自动**——永远扫整个客户端窗口（`regions()` 恒给一个矩形），对话框/任务栏靠文字认。**手动框选已删除**（用户 2026-10-17：不支持手动框了），也没有 `bell_rect` 配置。**注意这条说的是"region 是哪块"，跟"整窗扫"不是一回事**：整窗扫说的是那一拍在 region 里读整块（只为定位任务栏框，见下面）。
  - 地图名必须过 `known_map()`（= 归一后属于那六张；**用户确认铃铛只去这六张**，所以"某某地(12,34)"这种一律不认，别的任务/聊天的地点不会误当成妖魔位置）；`_RE_BELL_KNOWN` 兜底认"没锚点但图名认识"的老写法（**只在读红框那一块时用**，整窗那一拍不用它，见下）。
- **地图名要能容忍 OCR 认错字**：`_BELL_CANON` 收常见错法（实测把"建邺城"读成**建邮城**，整条提示就废了；还有 西粱/宝像/敖来/常寿/长寿郊外），`known_map()` 最后还兜一条"**对得上至少两个字且只对得上这一张**"（治"宝象国"被读成"宝国"）。新增地图名时把错法一起补进去 —— 宁可多认几个字，别漏掉整条提示；但也别放太松（"长安"跟"长寿村"只共一个"长"，放进来就会把别的任务当成铃铛）。
- **任务追踪里挂着多个任务,只认「降妖伏魔」标题下的那一段**（`_bell_scope`）：别的任务也有"去某某地(x,y)"的行,不圈范围就会认错。保留三种块：①标题下 200px 内的行 ②对话框说的（「踪迹在…」/「去X(x,y)使用招魂帖」）③「妖魔在…」（这句话只有铃铛任务会说,标题被 OCR 漏了也能兜住）。找不到标题时,任务追踪的行全部作废,只剩对话框。

## 全部细节（原文，2026-10-17 从 AGENTS.md 原样搬来）

**底图现在随仓库分发**（2026-10-21 用户定的，提交 `a2023ae`）：`data/maps/` 下是六张官方地图截图（`<中文名>.png`）+ `bounds.json`（坐标范围）+ `calib.json`（坐标↔像素标定），clone 下来即可用。**想自己重采仍可**（`gui.record_map`，界面入口已撤，见下）；原项目一度因为游戏素材的版权风险把底图全部删掉、只留一键录入，那是本应用之前的状态。

- `tools/bell.py:find_map_rect(rgb, want_ratio=None)`：**两条路互补**，返回 `(x0,y0,x1,y1)` 或 `None`。
  1. `find_color_blob`：逐级试彩色度档 `sat>35/25/45/55`，每档取"边长 160~1500 + 连通块占外接框 ≥0.55"的块，再按"外接框长宽比离 `want_ratio` 最近"打分（偏差 >3% 不要）；每块还按"行/列覆盖比例 ≥0.5 的最长连续段"裁一次当第二候选。五张图靠它命中（0.2~0.5s，全屏约 1.4s）。
  2. `find_map_frame`（兜底）：**地图窗那圈深色外框**。判据是"细深色长条"——某行/列有很长的深色连续段，且这一段**外面至少一侧是亮的**（是线，不是深色面积块）；上下两条横线的跨度要基本重合、左右两条竖线的跨度要落在两条横线之间，四条线框出的矩形边长在区间内、长宽比离 `want_ratio` 差不超过 12%（外框比本体多一圈边，比例会漂），然后在框内**再跑一次 `find_color_blob`** 拿到本体。**建邺城（灰石头城，彩色度全图最低）只有这条路认得出**（1.4~5.6s）。
  - 实测（把官方地图窗截图贴进真游戏截图做的全屏模拟）：**六张全部命中，与地图本体差 ≤1px；三张没开地图的真截图 × 六张图 = 18 个反例全部拒**。`want_ratio` 由 `map_ratio(name)` 从 bounds.json 算（六张图与底图差 ≤1%），既是挑选依据也是校验。
- `tools/bell.py:map_names_in(blocks)`：画面文字里出现过哪几张地图名（去重 + 别名归一）。核对规则：录的那张没出现在画面里、却读到了另一张 → 拒绝；一张都没读到 → 仍然放行但在日志里写明"没读到地图名(没核对)"。地图窗口里那些**邻近**地图的标注（解阳山/丝绸之路…）不在 `BELL_MAP_NAMES` 里，不会被算进来。
- **降妖伏魔小窗只有一扇窗**：没有顶栏（牌匾和「地图采集」按钮 2026-10-20 撤了），卡片里是「大字坐标 + 400×280 底图(红点) + 提示行 + 一颗「自动定位」」；右侧抽屉照建但**没有入口**（见下面那条）。**没有「降妖伏魔」抬头**（2026-10-21 用户定的：不要抬头，面板头整条删了）。
- 底下只有一颗「自动定位」按钮（`ui/bell.py:build_bell`）：定位到客户端后按钮上的字换成**那台客户端的角色名**（`client_name(bell_client)`）；没定位到还是「自动定位」。**客户端矩形不再显示**（用户 2026-10-20）；**「自动监听」「日志 ▾」按钮同日撤掉**（监听常开；日志区后来 2026-10-21 也整个撤了）；更早的「框选区域」「清除」已删（用户 2026-10-17：手动框选不支持了）。
- **只支持两档分辨率**（640x480 / 800x600，窗口分别是 815x680 / 1011x826）。**1024x768（窗口 1291x1025）已不支持**，表里那一行已删；自动定位到别的尺寸时 `check_size()` 会记下 `bad_size`，界面轮询到就**弹框提醒用户改分辨率**（同一个尺寸只弹一次），同时 `fixed_dialog()` 仍按比例兜底跑（识别可能不准）。数据是用户在截图上**画红框**标的，我从图里量出来写进表的 —— 红框比自动找面板可靠：暗场景里"对话框"和它身后的暗区像素上分不开（实测都是 (8,14,20) 那种深蓝黑，`panel_box` 会糊成一大片）。
- **量过的尺寸不用 `panel_box` 找面板**：位置是死的，直接按表裁那一块，只拿"这块够不够暗"当"现在有没有对话框"（`fixed_dialog()` 那条分支）。跨分辨率还暴露了一个老问题：`DIALOG_MIN_H=200` 是按 1024 档调的，**640x480 下对话框只有 165 高**，被它拒了。
- **分辨率表**（`data/bell_layouts.json`，`layout_for()` / `save_layout()`）：支持的两档尺寸下**位置固定的两样** —— 对话框（`dlg`）和**任务栏框（`trk`）**在哪（2026-10-17 用户要求：**量过的尺寸把任务栏框也写进表，这个分辨率以后只扫那一块**，不再花 2~3 秒整窗找 —— 两档都是用户在**原始尺寸截图**上框的（2026-10-17 晚，以他框的为准）：815x680 `trk=[562,162,807,373]`、1011x826 `trk=[764,160,1007,395]`（1015x828 那台实测窗口命中同一行）。框比 `track_rect` 学出来的宽：左边留 48px（旧框只剩 6px，差点切字）、下边留 67~89px（逐妖蛊虫 3~4 行的尾巴不会再掉），`layout_trk(size)` 读它，`save_layout(size, dlg=…, trk=…)` 写它）。**不在表里的尺寸 = 不支持**（`check_size()` 记 `bad_size`、界面弹窗让用户改分辨率）；兜底仍按窗口比例猜对话框、任务栏临时整窗找。`measure_layout` 只量对话框那一块、连 OCR 都不用开，`--layout` 也不问任务栏。老版本留下的 `icons` 键在 `save_layout` 重写那一行时顺手 `pop` 掉(`trk` 是现在正在用的键,别再清)（`icons` 是"判进没进战斗"那一格，那个功能已删，见下面那条）。坐标存的是**相对客户端窗口左上角**，所以窗口挪了、多开都不用重设。优先级：**分辨率表 > 按窗口比例猜（不支持尺寸的兜底）**。量取用 `python main.py --layout`（得**当下开着对话框**才量得到；量出来的框要是快盖满整条带子，多半是没开对话框把整条带子当面板了，`measure_layout` 会跳过不写）。量的时候**必须 `core._dpi_aware()`** —— 不然量的是逻辑像素，和主程序（物理像素）对不上，存进去的坐标全错（踩过）。
- **降妖伏魔只认一台客户端**（`regions()` 恒返回一个矩形）：多开时界面弹列表让用户**按角色名**选（`client_choices()` / `client_name()` 从窗口标题抠名字，如 `梦幻西游 ONLINE - (湖北2区[黄鹤楼] - 祭花′[29024311])` -> `祭花′`），选择存 `bell_client`。**进功能自动定位到就当场落盘**（2026-10-17 改）：单台也直接写 `bell_client`，按钮变成角色名（矩形不再显示，用户 2026-10-20）；多开且没选过会弹一次列表。「自动定位」按钮点了会重新找并保存。
